# NoWorryCV

NoWorryCV 是一个由网页工作台和 Chrome 插件组成的求职助手，将基础资料管理、岗位简历定制、申请表填写和版本保存连接起来。

**准备一次真实资料，针对每个岗位生成简历，确认后填写并保存。**

当前提供可在本地运行的 MVP。网页负责资料确认、简历编辑与导出；插件负责在招聘页面识别岗位、展示微调简历，并在用户确认后填写申请表。

## 核心流程

```text
上传基础简历 → 核对基本信息、项目、实习经历和事实 → 保存基础档案
                                                        ↓
招聘页面识别岗位要求 → 复用基础档案 → 生成并审查微调简历
                                                        ↓
检查简历与逐字段预览 → 用户确认 → 保存简历快照并填写申请表
                                                        ↓
检查未填写项和附件 → 用户手动提交
```

首次使用时，上传 PDF、DOCX、Markdown 或 TXT 简历，修正解析结果并确认事实来源。资料不足时可以回答补充问题；明确同意保存后，这份基础档案可以用于后续岗位。

投递时，插件识别岗位职责和任职要求，结合已确认的资料调整简历表达与内容顺序。用户可以检查风险提示、修改简历、编辑或禁用待填写字段。确认后，系统先保存该岗位对应的简历，再填写页面并记录结果。

如果只需要定制简历，也可以直接在网页粘贴岗位描述（JD），生成、编辑并导出，无需安装插件。

## 已有能力

| 环节 | 当前能力 |
| --- | --- |
| 基础资料 | 简历解析、事实确认与编辑、缺失信息追问、基础档案保存与复用 |
| 岗位定制 | JD 分析、相关经历筛选与改写、事实溯源、真实性审查和匹配参考分 |
| 用户审阅 | 原文与改写对比、逐条接受或拒绝、结构化编辑、局部重写、版本恢复 |
| 简历交付 | 纯文本与 Markdown 复制、DOCX/PDF 导出、网页分页预览 |
| 页面填写 | 岗位与字段识别、填写预览、动态经历区块展开、原生简历附件填写、文本撤销 |
| 保存与恢复 | 任务历史、版本管理与对比、已确认投递快照、填写报告、失败阶段重试 |

网页的完整生成流程还会提供 JD 复习文档和面试准备文档。插件使用投递模式，保留岗位分析、简历改写与审查，跳过这些准备材料以减少等待。

## 快速开始

需要 Python 3.9+；使用插件需要 Chrome 116+。插件无需单独构建。

### 1. 安装依赖

在仓库根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

### 2. 配置模型

首次配置时复制模板；已有 `.env` 时直接编辑现有文件。

```bash
cp .env.example .env
```

模板默认使用 Qwen。在 `.env` 中填写自己的密钥，并按所用服务设置模型与接口地址：

```dotenv
LLM_PROVIDER=qwen
QWEN_API_KEY=your_qwen_api_key
QWEN_MODEL=qwen-plus
```

也支持兼容接口：设置 `LLM_PROVIDER=openai_compatible`，并填写 `LLM_API_KEY`、`LLM_MODEL` 和 `LLM_BASE_URL`。完整配置项见 [.env.example](.env.example)。密钥保留在本地 `.env` 中。

### 3. 启动网页工作台

```bash
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

打开 [网页工作台](http://127.0.0.1:8000/app/)。上传简历，核对资料与事实，保存基础档案；或粘贴 JD，直接开始网页定制流程。接口文档位于 [Swagger UI](http://127.0.0.1:8000/docs)。

### 4. 加载 Chrome 插件

1. 打开 `chrome://extensions`，开启开发者模式。
2. 点击「加载已解压的扩展程序」，选择本仓库的 `extension/` 目录。
3. 保持 NoWorryCV 网页打开，点击插件图标，在侧栏读取网页已保存的基础档案。
4. 切换到招聘页面，检查识别出的岗位、微调简历和填写预览，再确认填写。

插件的服务地址必须与网页地址一致。首次连接后可复用已保存的连接信息。岗位详情和申请表分属不同页面时，可在申请页选择「沿用上次识别岗位」。完整操作见 [插件使用说明](extension/README.md)。

## 数据保存与用户控制

简历改写以用户确认的事实为依据，岗位要求用于选择重点和调整表达。缺失信息需要用户补充；无法溯源或可能夸大的内容会提示复核。JD 匹配参考分用于比较当前岗位与简历内容，不代表面试、录用或 ATS 通过概率。

| 数据 | 默认保存规则 |
| --- | --- |
| 生成任务、编辑版本、未确认投递预览 | 默认 24 小时，到期自动清理；任务归档不延长保存期限 |
| 已确认的基础档案 | 明确同意长期保存后，保留至主动删除 |
| 已确认的岗位简历与填写结果 | 明确同意长期保存后独立保留，原生成任务过期不影响快照 |

已确认的投递快照保留当时的岗位要求、资料版本、简历与事实来源，后续编辑草稿或更新基础档案不会改变它。可以单独删除投递记录；删除基础档案也会删除其投递记录，已生成的匿名任务仍按原有期限和删除机制管理。

访问凭据保存在当前浏览器，资料和简历由本地后端存储，默认位于 `.dist/`。生成时相关材料会发送至配置的模型服务。当前没有账号登录和跨设备同步；清除浏览器存储可能导致访问凭据丢失。

## 当前支持范围

- **表单适配**：支持顶层页面的标准输入框、文本域、下拉框和原生文件字段。复杂控件、跨域 iframe、Shadow DOM、验证码及多步投递仍需手动处理或站点适配。
- **识别与填写**：岗位识别结果可修正；未知问题和缺失资料可在预览中补充。附件被控件接收后，仍需检查站点是否完成上传。最终提交由用户操作。
- **简历质量**：效果依赖基础资料、JD 完整度和模型输出；扫描件或复杂排版可能影响解析。生成耗时取决于模型与内容长度。
- **运行环境**：插件当前连接本机 HTTP 服务，尚未提供面向公开部署的账户与租户体系。

## 开发与验证

项目使用 FastAPI 提供接口，LangGraph 编排生成与审查流程，SQLite 保存任务队列、基础档案和投递快照。插件采用 Manifest V3，整合了 JobAutoAgent 初版的表单识别与填写引擎。

```text
backend/app/       接口、生成流程、数据存储和网页工作台
backend/tests/     后端测试
extension/         Chrome 侧栏、页面识别和填写引擎
prompts/v1/        各生成与审查阶段的提示词
feature_list.json  功能清单、完成状态和后续规划
```

运行验证：

```bash
python -m pytest -q
node --test extension/tests/form_engine.test.cjs
```

后端测试使用 stub 模型验证流程，不调用真实模型。插件的本地模拟投递页与手动验收步骤见 [插件说明](extension/README.md#验证)。功能状态与后续规划见 [功能清单](feature_list.json)。
