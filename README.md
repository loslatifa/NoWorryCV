# NoWorryCV

NoWorryCV 是一个针对求职场景设计的简历定制与面试准备工具。  
你上传一份基础简历，再粘贴目标岗位 JD，系统会生成一份更贴合该岗位的简历版本，同时给出匹配分析、修改说明、风险提示、JD 复习文档，以及基于最终简历整理的面试准备文档。

## 这个工具能做什么

- 根据不同 JD 生成定制版简历
- 在生成前确认并修正简历解析结果与事实卡
- 尽量突出和岗位更相关的真实经历、项目和技能
- 区分 `校招 / 社招 / 实习` 三类招聘场景
- 输出 ATS 友好的 Markdown 简历
- 给出匹配摘要、修改说明和风险提示
- 逐条对比原简历与定制版本，查看事实来源并接受或拒绝修改
- 复制纯文本或 Markdown，并导出单栏 ATS 友好的 DOCX 和 PDF
- 在等待过程中展示与当前 JD 相关的复习卡片，支持手动切换上下一个知识点
- 生成一份 `JD 复习文档`，帮助你快速理解岗位重点和基础知识点
- 生成一份 `面试准备文档`，帮助你围绕定制后的简历准备八股、项目深挖和行为题

## 使用前准备

1. 准备一份基础简历
支持格式：
- `PDF`
- `DOCX`
- `Markdown`
- `TXT`

2. 准备目标 JD
- 建议尽量粘贴完整 JD
- 最好包含岗位职责、任职要求、加分项

3. 配置模型密钥
- 把 `.env.example` 复制为 `.env`
- 在 `.env` 中填入你自己的模型 key

```bash
cp .env.example .env
```

## 如何启动

先安装依赖并启动服务：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install ".[dev]"
PYTHONPATH=. uvicorn backend.app.main:app
```

启动后打开：

```text
http://127.0.0.1:8000/app/
```

## 如何使用

1. 上传简历文件
- 推荐上传可复制文字的 PDF 或标准 DOCX

2. 粘贴目标 JD
- JD 越完整，结果通常越稳定

3. 填写候选人备注
- 比如“希望强调数据分析”“希望偏增长产品方向”

4. 选择输出语言和自动迭代轮数
- 如果不确定，语言可以选“自动跟随 JD”
- 迭代轮数越多，系统会多做几轮优化，但等待时间也会更长

5. 点击“解析简历并确认”
- 核对姓名、联系方式、经历结构和个人摘要
- 逐条确认、编辑、删除事实卡，或补充遗漏事实
- 回答系统根据 JD 缺口提出的关键问题，也可以明确选择无法提供或暂时跳过
- 低置信度内容会被醒目标记，未确认事实不会进入后续生成流程

6. 点击“确认并生成定制简历”
- 页面会显示真实进度
- 系统会先分析 JD，再生成等待区的知识点复习卡片
- 你可以手动切换到上一个或下一个知识点
- 最终结果里会额外给出 `JD 复习文档` 和 `面试准备文档`

## 结果页怎么看

结果页主要看这几块：

- `JD 匹配参考分`
对比原简历和定制版本，并拆分展示核心关键词、可选关键词、结构和真实性维度。分数只用于当前 JD 的内容比较，不代表 ATS 通过概率、面试机会或录用结果。

- `真实性风险`
提示是否有可能存在无法追溯或表达过度的问题。

- `招聘类型`
系统会尝试识别这是校招、社招还是实习岗位。

- `匹配摘要`
简要说明这份简历为什么和当前 JD 匹配，或者主要差距在哪。

- `修改说明`
告诉你系统重点改了哪些方向。

- `风险提示`
提醒你哪些地方还需要人工确认。

- `原简历与定制版本对比`
按改写、新增和删除展示具体变化。点击定制内容可以查看事实来源；你可以逐条保留改写、使用原文、删除新增内容或恢复被删事实，无来源内容会显示高风险提示。

- `定制简历编辑器`
可以直接修改标题、摘要、技能、经历、项目和教育内容，支持撤销、恢复、保存历史版本，以及针对摘要、技能或单条 bullet 进行局部重写。保存后系统会重新计算真实性风险与 JD 匹配参考分；Markdown 正文可在编辑器底部展开预览。

- `复制与导出`
可以复制包含联系方式的纯文本或 Markdown。下载 DOCX、PDF 前必须先生成实际 PDF 分页预览；系统会显示页数，并在超过一页时提示精简内容。文件名支持中文和英文。

- `JD 复习文档`
帮助你快速理解这个岗位最看重什么、为什么重要、应该先复习什么。

- `面试准备文档`
围绕当前 JD 和当前简历版本，整理基础八股、项目经历深挖、行为题和风险提醒。

## 使用建议

- 一次只针对一个 JD 生成，不要把多个岗位要求混在一起
- 如果你的简历本身信息很少，先补充项目、实习、技能，再生成效果会更好
- 如果结果不够理想，可以调整候选人备注再跑一轮
- 校招岗位尽量保证教育、项目、实习信息完整
- 社招岗位尽量补充职责范围、业务结果和量化成果
- 等待时先浏览 JD 复习文档，结果出来后再重点看面试准备文档，会更容易形成完整准备闭环

## 注意事项

- 系统目标是“优化表达和重排信息”，不是替你编造经历
- 如果原始简历缺少某项经历，系统不应该凭空补出来
- PDF / DOCX 的解析效果依赖原始文件质量，扫描件或排版过于复杂的文件效果会差一些
- DOCX 和 PDF 使用 Letter 纸张的单栏 ATS 模板；内容较多时会保留完整内容并提示多页，不会自动删除经历

## 隐私与安全

- 真实 key 只应该放在本地 `.env`
- 不要把 `.env` 上传到 GitHub
- 仓库里保留的 `.env.example` 只是模板，不应填写真实密钥

如果你准备上传 GitHub，建议先运行：

```bash
PYTHONPATH=. python scripts/check_public_secrets.py
```

## 当前限制

- 当前仍是 MVP，结果质量依赖原始简历质量和 JD 完整度
- 某些复杂 PDF / DOCX 解析可能不稳定
- 极短 JD 或极短简历会明显影响结果质量
- 复习文档和面试准备文档目前以实用性为主，后续还会继续针对不同岗位族群细化
