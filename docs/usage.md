# 使用说明

[返回项目首页](../README.md)

## 核心流程

```text
上传基础简历 → 核对基本信息、项目、实习经历和事实 → 保存基础档案
                                                        ↓
招聘页面识别岗位要求 → 复用基础档案 → 生成并审查微调简历
                                                        ↓
检查简历与逐字段预览 → 用户确认 → 保存简历快照并填写申请表
                                                        ↓
检查未填写项和附件 → 用户手动提交
```

首次使用时，上传 PDF、DOCX、Markdown 或 TXT 简历，以原简历为准核对遗漏和识别错误。技能、工具和语言集中编辑，具体描述按工作或项目归组；原有内容默认保留，统一勾选采用资料即可继续。岗位相关补充问题为选填。明确同意保存后，这份基础档案可以用于后续岗位。

投递时，插件识别岗位职责和任职要求，结合已确认的资料调整简历表达与内容顺序。用户可以检查风险提示、修改简历、编辑或禁用待填写字段。确认后，系统先保存该岗位对应的简历，再填写页面并记录结果。

如果只需要定制简历，也可以直接在网页粘贴岗位描述（JD），生成、编辑并导出，无需安装插件。

保存基础档案后，可从网页或插件打开「职位投递工作台」（`/app/positions.html`）。按公司和职位保存 JD，记录待投递、已投递、笔试、面试、Offer 或关闭阶段，以及下一步行动和提醒时间。可以直接为职位创建生成任务，在工作台选择已保存版本或已确认的插件投递快照，也可从简历结果页直接关联当前版本。每个职位只有一个当前投递版本，历史材料仍保留；面试报告需另行同意长期保存。提醒在页面内显示，没有后台推送；插件“已填写”不会自动标记为“已投递”。

在「岗位与简历偏好」中选择目标地区和招聘场景，可保存为当前档案的常用偏好；插件会自动沿用，也可针对本次岗位覆盖。显式选择优先于自动识别，结果页保留原始识别供核对。美国、加拿大和默认设置使用 Letter，中国大陆、香港、新加坡、英国、欧洲使用 A4；导出版式使用可自动分页的单栏结构。页数是生成目标，导出前会按实际 PDF 分页提醒超出情况；DOCX 分页可能因本机字体和软件不同而变化。已生成任务和已确认投递快照保持当时的偏好，不随档案设置更新。

准备材料页的「简历模板」提供 18 份用户提供的模板适配版，以及原有 ATS 标准、ATS 紧凑两款基础版式。点击「选择模板」可浏览缩略图、放大查看实际 A4 示例 PDF，再将选择用于新任务；模板也可随档案常用偏好保存。结果页「导出与保存」支持更换本次导出模板，重新预览后下载 PDF 或 DOCX，无需重新生成正文。此处的换版只作用于本次导出；保存到职位或插件投递快照时沿用生成任务的模板。

模板采用自动分页的流式适配，保留源文件的配色、字体层次和章节顺序。深色标题条适配为同色标题与浅色底纹，兼容不显示底色的文档预览器。原稿的固定文本框、照片和装饰图形不会复制进用户简历；模板中的示例姓名、学校和经历也不会用于生成。PDF 优先嵌入可用的本机中文字体，否则使用内置中文字体。模板中的“双页”是参考版式，实际页数取决于内容和纸张设置。

后续添加或更新模板时，在项目虚拟环境中执行：

```bash
python scripts/import_resume_templates.py "/path/to/templates"
python scripts/render_resume_templates.py
```

导入支持 DOCX，其他格式和损坏文件会列出原因。生成缩略图需要 Poppler 的 `pdftoppm`（macOS 可通过 `brew install poppler` 安装）；已附带的缩略图可直接使用。完成导入及缩略图生成后重启后端并刷新网页。项目保存不含示例正文的版式配置和预览图片，运行时无需访问桌面原始目录。源文件发生变化会生成新的模板标识，旧配置保留供历史任务使用。

## 已有能力

| 环节 | 当前能力 |
| --- | --- |
| 基础资料 | 按完整经历解析核对与整段编辑、集中技能编辑、可选信息补充、基础档案保存与复用 |
| 岗位定制 | JD 分析、相关经历筛选与改写、事实溯源、真实性审查和匹配参考分 |
| 个性化 | 地区、岗位族、招聘类型、资历、语言、语气、页数及版式偏好，保存到档案并复用 |
| 简历模板 | 18 份提供的模板流式适配、缩略图与示例预览、生成前选择及导出时换版 |
| 求职材料 | 求职信、约 30 / 60 / 120 秒自我介绍、项目深挖讲稿、HR 话术，编辑核对与 Markdown / ZIP 导出 |
| 面试练习 | 基于已保存简历与 JD 分轮提问、回答追问、四维反馈、事实风险核对和复习报告 |
| 用户审阅 | 原文与改写对比、逐条接受或拒绝、原生及 React + TypeScript 结构化编辑、局部重写、版本恢复 |
| 简历交付 | 纯文本与 Markdown 复制、DOCX/PDF 导出、网页分页预览 |
| 页面填写 | 岗位与字段识别、填写预览、动态经历区块展开、原生日期与年月分栏、明确下拉选项匹配、原生简历附件填写、撤销 |
| 投递管理 | 公司与职位工作台、六种阶段、下一步行动、页面内提醒、时间线、独立材料归档 |
| 保存与恢复 | 任务历史、版本管理与对比、已确认投递快照、填写报告、失败阶段重试 |
| 反馈与评测 | 整份及单条修改评分、主动修改决策记录、质量概览、生成环境标识与合成样例回归 |

网页的完整生成流程还会提供 JD 复习文档和面试准备文档。插件使用投递模式，保留岗位分析、简历改写与审查，跳过这些准备材料以减少等待。

解析核对页将每段工作或项目的名称、岗位或角色、起止时间和完整正文放在同一张卡片中，正文以一个自然段阅读和编辑，来源文字默认收起。后台仍保留独立事实点；整段改写时保留未改动小点的 ID 和来源，只重新拆解修改部分。项目时间按原文精度保存，明确标注的角色与时间归入同一项目。补充资料默认独立保存，选择所属工作或项目后才合并；未指定归属的经历补充不自动写入生成简历。保存档案并重新载入后继续以完整段落编辑。

生成完成后，在网页「互动模拟面试」中选择 3–6 轮，用当前已保存版本开始练习。每轮最多追加一次追问；反馈引用回答原句，对照已确认事实提示数字、技术经历或职责边界风险，并提供结构、证据、清晰度和一致性建议。练习可以恢复、重复、提前结束或单独删除，复习报告可下载为 Markdown。回答不会自动加入事实库；只有已提交内容保存到服务端，并随原生成任务删除或到期清理。规则检查覆盖有限，真实模型反馈也需要本人复核。

在结果页「岗位求职材料包」中，用当前已保存简历生成七份材料。模型只选择与 JD 相关的事实和顺序，经历原句复用已确认事实，衔接语使用固定模板；没有事实支持的项目细节、到岗时间和沟通记录会保留待补充提示。三种自我介绍的时长是练习目标，实际长度受事实数量和语速影响。事实原句保留来源语言，跨语言材料可由本人核对翻译后编辑。

每份材料可独立编辑，保存后提示数字、技术、职责及占位内容风险；手工新增表达不会自动获得原事实引用的证明，也不会加入事实库。逐份勾选核对并保存后，可以下载单份 Markdown，全部核对后下载 ZIP。导出附来源版本、事实引用与原 JD，发送前可取用正文。材料绑定生成时的版本，后续切换或编辑简历不会改动它；本页未保存文字只暂存在内存。职位工作台可在核对版本、JD、材料修订并明确同意后长期保存整包，源任务到期不影响该快照。

## 数据保存与用户控制

简历改写以用户确认的事实为依据，岗位要求用于选择重点和调整表达。缺失信息需要用户补充；无法溯源或可能夸大的内容会提示复核。JD 匹配参考分用于比较当前岗位与简历内容，不代表面试、录用或 ATS 通过概率。

| 数据 | 默认保存规则 |
| --- | --- |
| 生成任务、编辑版本、反馈与行为记录、模拟面试会话、求职材料包、未确认投递预览 | 默认 24 小时，到期自动清理；任务归档不延长保存期限 |
| 已确认的基础档案 | 明确同意长期保存后，保留至主动删除 |
| 工作台职位、明确关联的简历、面试报告及求职材料包 | 同意长期保存后独立保留至主动删除，关闭职位不删除材料 |
| 已确认的岗位简历与填写结果 | 明确同意长期保存后独立保留，原生成任务过期不影响快照 |

已确认的投递快照保留当时的岗位要求、资料版本、简历与事实来源，后续编辑草稿或更新基础档案不会改变它。可以单独删除投递记录；删除基础档案也会删除其投递记录及职位工作台，已生成的匿名任务仍按原有期限和删除机制管理。工作台的材料快照独立保存，原任务到期或原投递记录删除不会影响它；删除职位会删除该职位内的快照，保留源任务和插件投递记录。

访问凭据保存在当前浏览器，资料和简历由本地后端存储，默认位于 `.dist/`。简历生成、材料证据选择及面试评估时，相关材料和面试回答会发送至配置的模型服务。当前没有账号登录和跨设备同步；清除浏览器存储可能导致访问凭据丢失。

## 当前支持范围

- **表单适配**：支持顶层页面的标准输入框、文本域、下拉框和原生文件字段。复杂控件、跨域 iframe、Shadow DOM、验证码及多步投递仍需手动处理或站点适配。
- **日期与选项**：原生日期和月份控件按已确认资料的精度填写，也支持可识别的年份、月份分栏。缺少具体日期或月份时提示手动补充；下拉选项要求唯一匹配，歧义、禁用或多选字段需手动处理。
- **识别与填写**：岗位识别结果可修正；未知问题和缺失资料可在预览中补充。附件被控件接收后，仍需检查站点是否完成上传。最终提交由用户操作。
- **简历质量**：效果依赖基础资料、JD 完整度和模型输出；扫描件或复杂排版可能影响解析。生成耗时取决于模型与内容长度。
- **运行环境**：插件当前连接本机 HTTP 服务，尚未提供面向公开部署的账户与租户体系。
